# 07C. StellarNet Lite 内置 ObjectSync 双端实操

本文不是再教你“额外造一套同步系统”，而是只教你一件事：

**怎么正确使用框架内置的 `Extensions/ObjectSync` 组件，把一个网络实体从 0 配出来，并在业务层补上你自己的 `C2S` 请求。**

这份文档专门面向新手，所以会明确拆开两层责任：

1. **框架内置 `ObjectSync` 自动负责的事**
2. **你业务层自己要写的事**

本文只讲两种最常见的业务同步分支：

1. `客户端请求输入`
2. `客户端请求位置转发`

请先记住一个结论：

**不管你走哪条业务分支，实体的生成、销毁、增量同步，仍然都应该继续走内置 `ObjectSync` 的 `S2C_ObjectSpawn / S2C_ObjectSync / S2C_ObjectDestroy`。**

你不要再额外定义一套 `S2C_ObjectSyncXXX` 去替代它。

---

## 1. 先讲清楚边界

### 1.1 内置 `ObjectSync` 已经帮你做了什么

内置 `ObjectSync` 已经负责了下面这些事：

1. 服务端维护同步实体容器
2. 给每个同步实体分配 `NetId`
3. 首次生成时发送 `S2C_ObjectSpawn`
4. 后续按脏字段发送 `S2C_ObjectSync`
5. 销毁时发送 `S2C_ObjectDestroy`
6. 客户端缓存同步状态
7. 客户端给 `NetTransformView` 提供预测后的位移数据
8. 客户端给 `NetAnimatorView` 提供预测后的动画数据
9. 支持回放快照导出与消费

对应核心类型就是这些：

- `ServerObjectSyncComponent`
- `ClientObjectSyncComponent`
- `ObjectSpawnerView`
- `NetIdentity`
- `NetTransformView`
- `NetAnimatorView`
- `ObjectSpawnState`
- `ObjectSyncState`
- `S2C_ObjectSpawn`
- `S2C_ObjectSync`
- `S2C_ObjectDestroy`

### 1.2 你业务层自己要写什么

你自己要写的，通常只有这几类：

1. `C2S` 请求协议
2. 服务端房间业务组件
3. 客户端输入或上报脚本
4. 房间启动时把 `ObjectSpawnerView` 和你的业务脚本初始化起来

也就是说：

**你自己写的是“请求”，不是“替换同步主链”。**

---

## 2. 一个同步实体从 0 到 1 需要准备什么

## 2.1 服务端房间组件

你的房间类型里，至少要有：

1. `RoomSettings`
2. `ObjectSync`
3. 你自己的业务房间组件

其中：

- `RoomSettings` 负责房间基础设置
- `ObjectSync` 负责内置实体同步
- 你的业务房间组件负责“什么时候生成实体、什么时候修改位置、什么时候切动画”

## 2.2 客户端房间组件

客户端房间里，至少要有：

1. `RoomSettings`
2. `ObjectSync`

通常不需要为了实体同步再额外做一个“自定义同步接收组件”。

原因很简单：

`ClientObjectSyncComponent` 已经在接收内置的：

- `S2C_ObjectSpawn`
- `S2C_ObjectSync`
- `S2C_ObjectDestroy`

你只要把视图层接上去就行。

## 2.3 客户端场景里要放什么

至少要有一个场景对象挂：

- `ObjectSpawnerView`

它的职责是：

1. 监听实体生成事件
2. 根据 `PrefabHash` 找到预制体
3. 实例化对象
4. 绑定 `NetIdentity / NetTransformView / NetAnimatorView`
5. 在实体销毁时清掉实例

如果你还要发输入或位置请求，通常还会在同一个场景根对象上再挂你自己的脚本，例如：

- `PlayerInputRequestController`
- `PlayerTransformForwardController`

## 2.4 客户端实体 Prefab 要挂什么

建议实体根节点至少挂这些：

- `NetIdentity`
- `NetTransformView`
- `NetAnimatorView`

如果实体有动画，还要有：

- `Animator`

如果实体要在本地做角色控制或碰撞，通常还会有：

- `CharacterController`

推荐层级示例：

```text
PlayerRoot
|- NetIdentity
|- NetTransformView
|- NetAnimatorView
|- CharacterController
|- VisualRoot
   |- Animator
   |- Mesh / Model / Bones ...
```

## 2.5 `NetTransformView` 是干什么的

`NetTransformView` 不是发包组件，它只是**表现层消费组件**。

它每帧会做的事是：

1. 用 `NetIdentity.NetId` 找到自己对应的同步实体
2. 向 `ClientObjectSyncComponent` 读取预测后的 `PredictedTransformData`
3. 把位置、旋转、缩放平滑应用到 Unity `Transform`

关键字段作用：

- `PosSmoothTime`
  远端位置平滑时间
- `RotSmoothSpeed`
  远端转向插值速度
- `SnapThreshold`
  偏差太大时直接瞬移到服务器结果
- `CatchUpThreshold`
  偏差中等时加快追赶
- `StopThreshold`
  目标几乎停止时直接落点，避免抖动

## 2.6 `NetAnimatorView` 是干什么的

`NetAnimatorView` 也不是发包组件，它只是**动画表现层消费组件**。

它每帧会做的事是：

1. 用 `NetIdentity.NetId` 找到自己的同步实体
2. 从 `ClientObjectSyncComponent` 读取 `PredictedAnimatorData`
3. 根据逻辑状态名映射到 Animator State
4. 根据逻辑参数名映射到 Animator Float 参数
5. 平滑应用参数
6. 处理防滑步与回放播放速度

你真正要配置的重点有两块：

1. `SyncedStates`
2. `SyncedFloatParams`

示例：

- `SyncedStates`
  - `LogicStateName = Locomotion`，`AnimatorStateName = Locomotion`
  - `LogicStateName = Attack`，`AnimatorStateName = Attack`
- `SyncedFloatParams`
  - `LogicParamName = MoveX`，`AnimatorParamName = MoveX`
  - `LogicParamName = MoveY`，`AnimatorParamName = MoveY`
  - `LogicParamName = MoveSpeed`，`AnimatorParamName = MoveSpeed`

请注意：

**服务端写的是逻辑名，客户端 `NetAnimatorView` 决定这些逻辑名映射到 Animator 里的哪个真实 State / Parameter。**

## 3. 整条链路到底怎么跑

无论你走“客户端请求输入”还是“客户端请求位置转发”，主链都是下面这样：

1. 客户端发一个 `C2S` 请求给服务端
2. 服务端房间组件收到请求
3. 服务端找到对应的 `ServerSyncEntity`
4. 服务端写入：
   - `Position`
   - `Rotation`
   - `Velocity`
   - `SetAnimState(...)`
   - `SetAnimParam(...)`
5. `ServerObjectSyncComponent` 在后续 Tick 中自动做脏检查
6. 框架自动发出：
   - `S2C_ObjectSpawn`
   - `S2C_ObjectSync`
   - `S2C_ObjectDestroy`
7. `ClientObjectSyncComponent` 自动接收并缓存
8. `ObjectSpawnerView` 负责生成对象
9. `NetTransformView / NetAnimatorView` 负责把状态表现出来

所以你要有一个很清晰的心智模型：

**业务层决定“真实状态是什么”，ObjectSync 负责“把真实状态发出去并在客户端表现出来”。**

## 4. 从 0 配出一个内置 ObjectSync 实体

下面按新手最容易照做的顺序来。

## 4.1 第一步：准备客户端预制体

先准备一个 `Player` 预制体。

根节点上建议直接挂好：

1. `NetIdentity`
2. `NetTransformView`
3. `NetAnimatorView`
4. `CharacterController`

子节点上挂：

1. `Animator`
2. 模型

为什么建议手动挂，而不是完全依赖运行时自动补？

因为：

1. 你需要在 Inspector 里配置 `NetTransformView`
2. 你需要在 Inspector 里配置 `NetAnimatorView`
3. 你需要让新手一眼就看清这个实体依赖哪些组件

## 4.2 第二步：配置 `NetAnimatorView`

假设你的 Animator Controller 里有这些状态：

- `Idle`
- `Locomotion`
- `Attack`

有这些 float 参数：

- `MoveX`
- `MoveY`
- `MoveSpeed`

那么 `NetAnimatorView` 可以这样理解：

### 状态映射

- `Idle`
  服务端想让它进入待机
- `Locomotion`
  服务端想让它进入移动 BlendTree
- `Attack`
  服务端想让它进入攻击状态

### 参数映射

- `MoveX`
  横向移动输入或混合值
- `MoveY`
  纵向移动输入或混合值
- `MoveSpeed`
  移动强度或速度倍率

这一步的本质是：

**让服务端写入的逻辑名字，能在客户端 Animator 里找到对应对象。**

## 4.3 第三步：把预制体放进可解析位置

让 `ObjectSpawnerView` 能根据 `PrefabHash` 找到这个预制体。

常见做法是：

1. 放到项目约定的 NetPrefab 目录
2. 重新生成 `NetPrefabConsts`

如果这一步没做，最常见结果是：

1. 服务端已经成功 `SpawnObject(...)`
2. 客户端也收到了 `S2C_ObjectSpawn`
3. 但是 `ObjectSpawnerView` 找不到预制体，场景里就是不出对象

## 4.4 第四步：服务端生成实体

服务端必须在房间组件里调用：

```csharp
ServerSyncEntity entity = _syncService.SpawnObject(
    NetPrefabConsts.NetPrefabs_Player,
    EntitySyncMask.All,
    spawnPosition,
    Vector3.zero,
    Vector3.zero,
    ownerSessionId);

entity.SetAnimState("Idle");
entity.SetAnimParam("MoveX", 0f);
entity.SetAnimParam("MoveY", 0f);
entity.SetAnimParam("MoveSpeed", 0f);
```

这里每个参数的意义都非常重要：

- 第 1 个参数 `prefabHash`
  客户端要生成哪个预制体
- 第 2 个参数 `EntitySyncMask.All`
  同步 Transform 和 Animator
- 第 3 个参数 `spawnPosition`
  初始位置
- 第 4 个参数 `rotation`
  初始欧拉角
- 第 5 个参数 `velocity`
  初始速度
- 第 6 个参数 `ownerSessionId`
  谁拥有这个实体

生成以后，内置 `ObjectSync` 会自动广播 `S2C_ObjectSpawn`。

## 4.5 第五步：客户端初始化 `ObjectSpawnerView`

最容易漏的就是这一步。

`ObjectSpawnerView` 不是自己就会工作，它需要你把当前 `ClientRoom` 传进去。

一个最小启动脚本可以这样写：

```csharp
using StellarNet.Lite.Client.Components.Views;
using StellarNet.Lite.Client.Core;
using UnityEngine;

namespace StellarNet.Lite.Game.Client.Views
{
    /// <summary>
    /// 客户端房间场景启动脚本。
    /// 负责把 ObjectSpawnerView 和业务输入脚本绑定到当前房间。
    /// </summary>
    public sealed class ClientRoomObjectSyncBootstrap : MonoBehaviour
    {
        public ObjectSpawnerView ObjectSpawner;
        public MonoBehaviour BusinessController;

        public void Init(ClientRoom room)
        {
            if (ObjectSpawner != null)
            {
                ObjectSpawner.Init(room);
            }

            if (BusinessController is IClientRoomInitializable initializable)
            {
                initializable.Init(room);
            }
        }
    }

    /// <summary>
    /// 让不同业务控制脚本都能统一接收 ClientRoom。
    /// </summary>
    public interface IClientRoomInitializable
    {
        void Init(ClientRoom room);
    }
}
```

这个脚本的作用很简单：

1. 初始化 `ObjectSpawnerView`
2. 初始化你自己的输入脚本

如果你漏了 `ObjectSpawner.Init(room)`，客户端就算收到了同步消息，也不会实例化实体。

## 5. 方案一：客户端请求输入

这是**更推荐**的新手路线。

它的含义不是客户端直接告诉服务器“我已经在哪了”，而是告诉服务器：

**“我现在按了什么输入，你来算最终结果。”**

这更接近服务端权威。

## 5.1 适用场景

适合：

1. 角色移动
2. 技能前摇
3. 服务端想严格控制移动合法性
4. 后面要继续扩展战斗判定

## 5.2 共享协议模板

下面是一个最小可复制的 `C2S` 输入请求：

```csharp
using System.IO;
using StellarNet.Lite.Shared.Core;
using StellarNet.Lite.Shared.Protocol;

namespace StellarNet.Lite.Game.Shared.Protocol
{
    /// <summary>
    /// 客户端只上报输入，不直接上报最终位置。
    /// 服务端收到后自己计算真实位移、朝向和动画。
    /// </summary>
    [NetMsg(1501, NetScope.Room, NetDir.C2S)]
    public sealed class C2S_PlayerInputReq : ILiteNetSerializable
    {
        /// <summary>横向输入，常见取值区间为 -1 到 1。</summary>
        public float MoveX;

        /// <summary>纵向输入，常见取值区间为 -1 到 1。</summary>
        public float MoveY;

        /// <summary>客户端希望角色面向的 Y 轴朝向。</summary>
        public float RotationY;

        public void Serialize(BinaryWriter writer)
        {
            writer.Write(MoveX);
            writer.Write(MoveY);
            writer.Write(RotationY);
        }

        public void Deserialize(BinaryReader reader)
        {
            MoveX = reader.ReadSingle();
            MoveY = reader.ReadSingle();
            RotationY = reader.ReadSingle();
        }
    }
}
```

### 字段说明

- `MoveX`
  横向输入，不是世界坐标
- `MoveY`
  纵向输入，不是世界坐标
- `RotationY`
  客户端期望面向角

### 这个协议为什么这样设计

因为这里的目标是：

1. 客户端只表达“意图”
2. 服务端自己算位置
3. 服务端自己决定动画状态

这样更适合生产环境下的服务端权威路线。

## 5.3 服务端房间组件模板

```csharp
using System.Collections.Generic;
using StellarNet.Lite.Game.Shared.Protocol;
using StellarNet.Lite.Server.Components;
using StellarNet.Lite.Server.Core;
using StellarNet.Lite.Shared.ObjectSync;
using StellarNet.Lite.Shared.Protocol;
using UnityEngine;

namespace StellarNet.Lite.Game.Server.Components
{
    /// <summary>
    /// 输入驱动的服务端权威同步模板。
    /// 客户端只发输入，服务端在 Tick 中计算真实位置与动画。
    /// </summary>
    [RoomComponent(160, "InputDrivenRoom", "输入驱动同步模板")]
    public sealed class ServerInputDrivenRoomComponent : ServerRoomComponent, ITickableComponent
    {
        private readonly ServerApp _app;
        private ServerObjectSyncComponent _syncService;

        /// <summary>SessionId 到 NetId 的映射，表示每个玩家对应哪个同步实体。</summary>
        private readonly Dictionary<string, int> _sessionToNetId = new Dictionary<string, int>();

        /// <summary>SessionId 到最后一帧输入的映射，表示服务端 Tick 要消费什么输入。</summary>
        private readonly Dictionary<string, PlayerInputState> _lastInputs = new Dictionary<string, PlayerInputState>();

        private const float MoveSpeed = 4f;
        private const int PlayerPrefabHash = NetPrefabConsts.NetPrefabs_Player;

        private struct PlayerInputState
        {
            public float MoveX;
            public float MoveY;
            public float RotationY;
        }

        public ServerInputDrivenRoomComponent(ServerApp app)
        {
            _app = app;
        }

        public override void OnInit()
        {
            _syncService = Room.GetComponent<ServerObjectSyncComponent>();
            _sessionToNetId.Clear();
            _lastInputs.Clear();
        }

        public override void OnGameStart()
        {
            foreach (var kvp in Room.Members)
            {
                SpawnPlayer(kvp.Value);
            }
        }

        public override void OnMemberJoined(Session session)
        {
            if (Room.State == RoomState.Playing)
            {
                SpawnPlayer(session);
            }
        }

        public override void OnMemberLeft(Session session)
        {
            if (session == null)
            {
                return;
            }

            if (_sessionToNetId.TryGetValue(session.SessionId, out int netId))
            {
                _syncService?.DestroyObject(netId);
                _sessionToNetId.Remove(session.SessionId);
            }

            _lastInputs.Remove(session.SessionId);
        }

        [NetHandler]
        public void OnC2S_PlayerInputReq(Session session, C2S_PlayerInputReq msg)
        {
            if (session == null || msg == null || Room.State != RoomState.Playing)
            {
                return;
            }

            _lastInputs[session.SessionId] = new PlayerInputState
            {
                MoveX = Mathf.Clamp(msg.MoveX, -1f, 1f),
                MoveY = Mathf.Clamp(msg.MoveY, -1f, 1f),
                RotationY = msg.RotationY
            };
        }

        public void OnTick()
        {
            if (Room.State != RoomState.Playing || _syncService == null)
            {
                return;
            }

            float deltaTime = 1f / _app.Config.TickRate;

            foreach (var kvp in _sessionToNetId)
            {
                string sessionId = kvp.Key;
                int netId = kvp.Value;

                ServerSyncEntity entity = _syncService.GetEntity(netId);
                if (entity == null)
                {
                    continue;
                }

                PlayerInputState input = _lastInputs.TryGetValue(sessionId, out PlayerInputState cachedInput)
                    ? cachedInput
                    : default;

                Vector3 moveDir = new Vector3(input.MoveX, 0f, input.MoveY);
                if (moveDir.sqrMagnitude > 1f)
                {
                    moveDir.Normalize();
                }

                Vector3 velocity = moveDir * MoveSpeed;

                entity.Position += velocity * deltaTime;
                entity.Velocity = velocity;
                entity.Rotation = new Vector3(0f, input.RotationY, 0f);

                UpdateAnimator(entity, input, velocity);
            }
        }

        private void SpawnPlayer(Session session)
        {
            if (session == null || _syncService == null || _sessionToNetId.ContainsKey(session.SessionId))
            {
                return;
            }

            ServerSyncEntity entity = _syncService.SpawnObject(
                PlayerPrefabHash,
                EntitySyncMask.All,
                Vector3.zero,
                Vector3.zero,
                Vector3.zero,
                session.SessionId);

            if (entity == null)
            {
                return;
            }

            entity.SetAnimState("Idle");
            entity.SetAnimParam("MoveX", 0f);
            entity.SetAnimParam("MoveY", 0f);
            entity.SetAnimParam("MoveSpeed", 0f);

            _sessionToNetId[session.SessionId] = entity.NetId;
        }

        private static void UpdateAnimator(ServerSyncEntity entity, PlayerInputState input, Vector3 velocity)
        {
            float speed01 = Mathf.Clamp01(velocity.magnitude / MoveSpeed);

            if (speed01 > 0.01f)
            {
                entity.SetAnimState("Locomotion");
            }
            else
            {
                entity.SetAnimState("Idle");
            }

            entity.SetAnimParam("MoveX", input.MoveX);
            entity.SetAnimParam("MoveY", input.MoveY);
            entity.SetAnimParam("MoveSpeed", speed01);
        }
    }
}
```

### 这个模板里每个字段是干什么的

- `_app`
  用来读取 TickRate，算每个 Tick 的 `deltaTime`
- `_syncService`
  房间里的内置 `ServerObjectSyncComponent`
- `_sessionToNetId`
  记录某个玩家对应哪个同步实体
- `_lastInputs`
  记录客户端最新输入，等待服务端 Tick 消费
- `MoveSpeed`
  服务端真实移动速度
- `PlayerPrefabHash`
  客户端应该生成哪个预制体

### 这个模板里每个关键函数是干什么的

- `OnInit()`
  拿到 `ServerObjectSyncComponent` 并清空缓存
- `OnGameStart()`
  房间开局时为已有成员生成实体
- `OnMemberJoined(...)`
  游戏中途加入也要补生成实体
- `OnMemberLeft(...)`
  玩家离开时销毁实体并清缓存
- `OnC2S_PlayerInputReq(...)`
  收输入，不直接改位置，只缓存
- `OnTick()`
  服务端权威计算真实位移、速度、朝向、动画
- `SpawnPlayer(...)`
  调内置 `SpawnObject(...)`
- `UpdateAnimator(...)`
  把逻辑状态和 BlendTree 参数写入 `ServerSyncEntity`

### 这条链路为什么靠谱

因为位置和动画结果都不是客户端最终决定的，而是：

1. 客户端只说“我按了什么”
2. 服务端统一算结果
3. 内置 `ObjectSync` 再把结果发回去

这比客户端直接上报最终位置更稳。

## 5.4 客户端输入脚本模板

```csharp
using StellarNet.Lite.Client.Core;
using StellarNet.Lite.Game.Shared.Protocol;
using UnityEngine;

namespace StellarNet.Lite.Game.Client.Views
{
    /// <summary>
    /// 客户端输入请求模板。
    /// 这里只负责采集输入并上报给服务端，不负责替代 ObjectSync。
    /// </summary>
    public sealed class PlayerInputRequestController : MonoBehaviour, IClientRoomInitializable
    {
        private ClientRoom _room;
        private float _lastSendTime;
        private const float SendInterval = 1f / 30f;

        public void Init(ClientRoom room)
        {
            _room = room;
            _lastSendTime = 0f;
        }

        private void Update()
        {
            if (_room == null || NetClient.State != ClientAppState.OnlineRoom)
            {
                return;
            }

            if (Time.realtimeSinceStartup - _lastSendTime < SendInterval)
            {
                return;
            }

            float moveX = Input.GetAxisRaw("Horizontal");
            float moveY = Input.GetAxisRaw("Vertical");

            Vector3 lookDir = new Vector3(moveX, 0f, moveY);
            float rotationY = transform.eulerAngles.y;
            if (lookDir.sqrMagnitude > 0.001f)
            {
                rotationY = Quaternion.LookRotation(lookDir).eulerAngles.y;
            }

            NetClient.Send(new C2S_PlayerInputReq
            {
                MoveX = moveX,
                MoveY = moveY,
                RotationY = rotationY
            });

            _lastSendTime = Time.realtimeSinceStartup;
        }
    }
}
```

### 这个客户端脚本负责什么

只负责：

1. 采集输入
2. 定时发 `C2S_PlayerInputReq`

它不负责：

1. 发 `S2C`
2. 管理实体生成
3. 替代 `ObjectSync`

### 这条方案的核心优点

1. 服务端权威更强
2. 后续做碰撞、技能、反作弊更顺
3. 动画状态也能在服务端统一决策

---

## 6. 方案二：客户端请求位置转发

这条路线的含义是：

**客户端先自己算出结果，再把位置、速度、朝向上报给服务端，服务端做校验后写回 `ServerSyncEntity`。**

它本质上是“客户端先算，服务端转发并兜底校验”。

## 6.1 适用场景

适合：

1. 轻交互社交房间
2. 原型验证
3. 对强对抗要求不高的同步场景

不太适合：

1. 强战斗
2. 严格防作弊
3. 高强度服务端判定项目

## 6.2 共享协议模板

```csharp
using System.IO;
using StellarNet.Lite.Shared.Core;
using StellarNet.Lite.Shared.Protocol;

namespace StellarNet.Lite.Game.Shared.Protocol
{
    /// <summary>
    /// 客户端把自己已经算出的结果转发给服务端。
    /// 服务端仍然要做距离、速度、状态合法性校验。
    /// </summary>
    [NetMsg(1502, NetScope.Room, NetDir.C2S)]
    public sealed class C2S_PlayerTransformForwardReq : ILiteNetSerializable
    {
        public float PosX;
        public float PosY;
        public float PosZ;
        public float VelX;
        public float VelY;
        public float VelZ;
        public float RotY;
        public float MoveX;
        public float MoveY;
        public float MoveSpeed;

        public void Serialize(BinaryWriter writer)
        {
            writer.Write(PosX);
            writer.Write(PosY);
            writer.Write(PosZ);
            writer.Write(VelX);
            writer.Write(VelY);
            writer.Write(VelZ);
            writer.Write(RotY);
            writer.Write(MoveX);
            writer.Write(MoveY);
            writer.Write(MoveSpeed);
        }

        public void Deserialize(BinaryReader reader)
        {
            PosX = reader.ReadSingle();
            PosY = reader.ReadSingle();
            PosZ = reader.ReadSingle();
            VelX = reader.ReadSingle();
            VelY = reader.ReadSingle();
            VelZ = reader.ReadSingle();
            RotY = reader.ReadSingle();
            MoveX = reader.ReadSingle();
            MoveY = reader.ReadSingle();
            MoveSpeed = reader.ReadSingle();
        }
    }
}
```

### 字段说明

- `PosX / PosY / PosZ`
  客户端当前实际位置
- `VelX / VelY / VelZ`
  当前速度
- `RotY`
  当前朝向
- `MoveX / MoveY / MoveSpeed`
  用来驱动动画 BlendTree 的逻辑参数

这里的重点是：

**位置和动画参数一起上报，这样服务端写回 `ServerSyncEntity` 时就能同时驱动 Transform 和 Animator。**

## 6.3 服务端房间组件模板

```csharp
using System.Collections.Generic;
using StellarNet.Lite.Game.Shared.Protocol;
using StellarNet.Lite.Server.Components;
using StellarNet.Lite.Server.Core;
using StellarNet.Lite.Shared.ObjectSync;
using UnityEngine;

namespace StellarNet.Lite.Game.Server.Components
{
    /// <summary>
    /// 位置转发模板。
    /// 客户端先算结果，服务端做校验，然后写入内置 ObjectSync 实体。
    /// </summary>
    [RoomComponent(161, "ForwardDrivenRoom", "位置转发同步模板")]
    public sealed class ServerForwardDrivenRoomComponent : ServerRoomComponent
    {
        private ServerObjectSyncComponent _syncService;
        private readonly Dictionary<string, int> _sessionToNetId = new Dictionary<string, int>();

        private const int PlayerPrefabHash = NetPrefabConsts.NetPrefabs_Player;
        private const float MaxMoveSpeed = 6f;
        private const float MaxDistancePerPacket = 1.5f;

        public override void OnInit()
        {
            _syncService = Room.GetComponent<ServerObjectSyncComponent>();
            _sessionToNetId.Clear();
        }

        public override void OnGameStart()
        {
            foreach (var kvp in Room.Members)
            {
                SpawnPlayer(kvp.Value);
            }
        }

        public override void OnMemberJoined(Session session)
        {
            if (Room.State == RoomState.Playing)
            {
                SpawnPlayer(session);
            }
        }

        public override void OnMemberLeft(Session session)
        {
            if (session == null)
            {
                return;
            }

            if (_sessionToNetId.TryGetValue(session.SessionId, out int netId))
            {
                _syncService?.DestroyObject(netId);
                _sessionToNetId.Remove(session.SessionId);
            }
        }

        [NetHandler]
        public void OnC2S_PlayerTransformForwardReq(Session session, C2S_PlayerTransformForwardReq msg)
        {
            if (session == null || msg == null || _syncService == null || Room.State != RoomState.Playing)
            {
                return;
            }

            if (!_sessionToNetId.TryGetValue(session.SessionId, out int netId))
            {
                return;
            }

            ServerSyncEntity entity = _syncService.GetEntity(netId);
            if (entity == null)
            {
                return;
            }

            Vector3 newPos = new Vector3(msg.PosX, msg.PosY, msg.PosZ);
            Vector3 newVel = new Vector3(msg.VelX, msg.VelY, msg.VelZ);

            if (Vector3.Distance(entity.Position, newPos) > MaxDistancePerPacket)
            {
                return;
            }

            if (newVel.magnitude > MaxMoveSpeed)
            {
                newVel = newVel.normalized * MaxMoveSpeed;
            }

            entity.Position = newPos;
            entity.Velocity = newVel;
            entity.Rotation = new Vector3(0f, msg.RotY, 0f);

            if (msg.MoveSpeed > 0.01f)
            {
                entity.SetAnimState("Locomotion");
            }
            else
            {
                entity.SetAnimState("Idle");
            }

            entity.SetAnimParam("MoveX", msg.MoveX);
            entity.SetAnimParam("MoveY", msg.MoveY);
            entity.SetAnimParam("MoveSpeed", Mathf.Clamp01(msg.MoveSpeed));
        }

        private void SpawnPlayer(Session session)
        {
            if (session == null || _syncService == null || _sessionToNetId.ContainsKey(session.SessionId))
            {
                return;
            }

            ServerSyncEntity entity = _syncService.SpawnObject(
                PlayerPrefabHash,
                EntitySyncMask.All,
                Vector3.zero,
                Vector3.zero,
                Vector3.zero,
                session.SessionId);

            if (entity == null)
            {
                return;
            }

            entity.SetAnimState("Idle");
            entity.SetAnimParam("MoveX", 0f);
            entity.SetAnimParam("MoveY", 0f);
            entity.SetAnimParam("MoveSpeed", 0f);

            _sessionToNetId[session.SessionId] = entity.NetId;
        }
    }
}
```

### 这个模板的关键点

- `OnC2S_PlayerTransformForwardReq(...)`
  直接接收客户端结果
- `Vector3.Distance(entity.Position, newPos) > MaxDistancePerPacket`
  校验一次包内位移是否过大
- `newVel.magnitude > MaxMoveSpeed`
  校验速度是否合法
- `entity.SetAnimParam(...)`
  直接把客户端算好的 BlendTree 参数写回去

### 这条路线的优缺点

优点：

1. 客户端体感更直接
2. 改起来快
3. 很适合参考 `Samples/SocialDemo`

缺点：

1. 服务端权威性弱于“输入请求”
2. 防作弊压力更大
3. 所有位置、速度、动画参数都需要额外校验

## 6.4 客户端转发脚本模板

```csharp
using StellarNet.Lite.Client.Core;
using StellarNet.Lite.Game.Shared.Protocol;
using UnityEngine;

namespace StellarNet.Lite.Game.Client.Views
{
    /// <summary>
    /// 客户端本地先移动，再把结果转发给服务端。
    /// 这是一条“位置转发”路线，不是替代内置 ObjectSync。
    /// </summary>
    public sealed class PlayerTransformForwardController : MonoBehaviour, IClientRoomInitializable
    {
        private ClientRoom _room;
        private CharacterController _controller;
        private float _lastSendTime;

        private const float SendInterval = 1f / 30f;
        private const float MoveSpeed = 4f;

        public void Init(ClientRoom room)
        {
            _room = room;
            _controller = GetComponent<CharacterController>();
            _lastSendTime = 0f;
        }

        private void Update()
        {
            if (_room == null || NetClient.State != ClientAppState.OnlineRoom || _controller == null)
            {
                return;
            }

            float moveX = Input.GetAxisRaw("Horizontal");
            float moveY = Input.GetAxisRaw("Vertical");

            Vector3 moveDir = new Vector3(moveX, 0f, moveY);
            if (moveDir.sqrMagnitude > 1f)
            {
                moveDir.Normalize();
            }

            Vector3 velocity = moveDir * MoveSpeed;
            _controller.Move(velocity * Time.deltaTime);

            float rotationY = transform.eulerAngles.y;
            if (moveDir.sqrMagnitude > 0.001f)
            {
                rotationY = Quaternion.LookRotation(moveDir).eulerAngles.y;
                transform.rotation = Quaternion.Euler(0f, rotationY, 0f);
            }

            if (Time.realtimeSinceStartup - _lastSendTime < SendInterval)
            {
                return;
            }

            NetClient.Send(new C2S_PlayerTransformForwardReq
            {
                PosX = transform.position.x,
                PosY = transform.position.y,
                PosZ = transform.position.z,
                VelX = velocity.x,
                VelY = velocity.y,
                VelZ = velocity.z,
                RotY = rotationY,
                MoveX = moveX,
                MoveY = moveY,
                MoveSpeed = Mathf.Clamp01(velocity.magnitude / MoveSpeed)
            });

            _lastSendTime = Time.realtimeSinceStartup;
        }
    }
}
```

### 这个脚本里每个关键步骤的意义

1. 本地先采集输入
2. 本地先算移动结果
3. 本地把位置、速度、朝向、动画参数一起发给服务端
4. 服务端校验后写入 `ServerSyncEntity`
5. 内置 `ObjectSync` 再统一广播给所有客户端

这意味着：

**就算是位置转发路线，最终同步主链仍然还是内置 `ObjectSync`。**

## 7. 两种方案怎么选

如果你现在要做生产环境项目，我更建议优先用：

1. `客户端请求输入`

原因是：

1. 更接近服务端权威
2. 更容易做规则收敛
3. 后续扩展战斗和判定成本更低

如果你现在是：

1. 社交房间
2. 原型验证
3. 快速搭建 Demo

那也可以先用：

1. `客户端请求位置转发`

但要记住，它是“快”，不是“更稳”。

## 8. 新手最容易踩错的地方

## 8.1 错误一：自己再定义一套 `S2C_ObjectSyncXXX`

这是本文最想避免的误区。

内置已经有：

1. `S2C_ObjectSpawn`
2. `S2C_ObjectSync`
3. `S2C_ObjectDestroy`

你应该自己补的是：

1. `C2S_PlayerInputReq`
2. `C2S_PlayerTransformForwardReq`

而不是再造一个“新的实体同步主协议”。

## 8.2 错误二：忘了初始化 `ObjectSpawnerView`

如果没调：

```csharp
ObjectSpawner.Init(room);
```

客户端就不会根据同步消息生成实体实例。

## 8.3 错误三：服务端改了位置，却没改动画

如果你只写：

```csharp
entity.Position = newPos;
```

却不写：

```csharp
entity.SetAnimState(...);
entity.SetAnimParam(...);
```

那么客户端可能会出现：

1. 位置在动
2. 动画还是待机

## 8.4 错误四：`NetAnimatorView` 没配映射

服务端写的是逻辑名，比如：

- `Locomotion`
- `Attack`
- `MoveSpeed`

客户端如果没在 `NetAnimatorView` 里把这些逻辑名映射到真实 Animator 对象上，就会出现：

1. 服务端数据在发
2. 客户端动画不切
3. 控制台出现 unmapped warning

## 8.5 错误五：把“位置转发”误以为“服务端权威”

位置转发不是纯服务端权威。

它只是：

1. 客户端先算
2. 服务端再校验和转发

如果项目要做严肃对抗，一定还是优先考虑“输入请求”路线。

---

## 9. 你现在应该怎么落地

如果你是第一次做，建议直接按这个顺序：

1. 先把 `Player` 预制体挂好 `NetIdentity / NetTransformView / NetAnimatorView / Animator`
2. 配好 `NetAnimatorView` 的 `SyncedStates` 和 `SyncedFloatParams`
3. 确保 `NetPrefabConsts` 已重新生成
4. 服务端房间里接入 `ServerObjectSyncComponent`
5. 客户端场景里放 `ObjectSpawnerView`
6. 先做 `客户端请求输入` 版本
7. 跑通后，如果你的项目确实更适合，再考虑 `客户端请求位置转发`

---

## 10. 一句话记忆

**内置 `ObjectSync` 负责生成、销毁、增量同步和表现层消费；你业务层只需要补自己的 `C2S` 请求，并在服务端把最终结果写回 `ServerSyncEntity`。**
